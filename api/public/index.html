① 平台 key 是什么

平台 key（形如 sk-xxxxxxxx）是本平台签发的代理凭证。它不是任何上游厂商的密钥——真正调用上游时，网关会自动换成服务端配置的上游密钥。

你的程序 ──sk-平台key──▶ 本平台网关 ──换成上游真key──▶ Ollama / SLCH / 算力节点
                                    │
                                    └─ 鉴权 · 路由 · 熔断 · 计费 · 日志
  • ✅ 上游密钥永不外泄：你只拿到平台 key，随时可禁用/删除，不动上游
  • ✅ 按令牌计量计费：谁用了多少、花了多少，一目了然
  • ✅ 模型白名单：一个令牌可限定只能用某几个模型
  • ✅ 多渠道故障转移：上游挂了自动切下一个，并跳过熔断渠道
  • ✅ 限流 / 额度 / IP 白名单 / 过期时间，全部可配

💡 一句话：平台 key = 受控的代理凭证。你把它当 OpenAI key 用即可，实际请求都经本平台转发。

⭐ 复制即用（把 sk-你的令牌 换成你自己的 key 即可）

把下面片段里的 sk-你的令牌 替换成你在「令牌」页创建的 key，直接粘贴到对应工具里就能用。

② 快速开始

只需两样东西：base_url 指向本平台，api_key 换成你的 sk- 令牌。无需改动任何调用代码。

curl http://127.0.0.1:58881/v1/chat/completions \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer sk-你的令牌" \
  -d '{
    "model": "deepseek-v4.1-flash",
    "messages": [{"role":"user","content":"你好"}],
    "stream": false
  }'

先验证连通性（列出令牌可见的全部模型）：

curl http://127.0.0.1:58881/v1/models \
  -H "Authorization: Bearer sk-你的令牌"

    model="deepseek-v4.1-flash",

# 流式

    model="deepseek-v4.1-flash",
    messages=[{"role": "user", "content": "讲个笑话"}],
    stream=True,
):
    print(chunk.choices[0].delta.content or "", end="")

任意 OpenAI 兼容客户端（Cherry Studio / NextChat / LobeChat / Cursor / Continue / Dify …）

  • API 地址（Base URL）：http://127.0.0.1:58881/v1
  • API Key：sk-你的令牌
  • 模型：填本平台「模型目录」里的名称（如 deepseek-v4.1-flash）

④ 可用端点

  • GET /v1/models — 列出令牌可见模型
  • POST /v1/chat/completions — 对话补全（支持 stream）
  • POST /v1/completions — 文本补全
  • POST /v1/embeddings — 向量
  • POST /v1/audio/* — 音频（取决于上游渠道是否支持）

全部为 OpenAI 兼容格式，请求/响应结构与官方一致。

⑤ 令牌能力与用法

  • 模型白名单：在「令牌」页给令牌填「限定模型」（逗号分隔），留空 = 不限；越权模型返回 403
  • 额度：可设「不限额度」或「固定金额」；令牌额度用尽返回 402。用户账户余额为 0 同样 402
  • IP 白名单：填允许的 IP（逗号分隔），留空 = 不限；非白名单来源 403
  • 过期时间：可设令牌到期时间，过期后 401
  • 限流：按令牌滑动窗口限流（阈值见「系统设置」），超限返回 429 并带 Retry-After 头
  • 启用/禁用：随时在「令牌」页开关，禁用后立即 403

🔑 令牌明文仅在创建时显示一次，请立即保存；平台仅存哈希，无法找回，丢了就重新生成。

⑥ 计费说明

  • 按 输入 + 输出 tokens 计费，单价见「模型目录」（USD / 1M tokens）
  • 优先采用上游返回的真实 usage；上游未返回时按中文≈1 token/字、英文≈1 token/4 字符估算兜底
  • 扣费三方同步：用户余额 · 令牌用量 · 渠道用量，并写日志
  • 可在「日志」页查看每次调用的 tokens / 花费 / 用时，并导出 Excel

⑦ 路由与故障转移

  • 同一模型可由多个渠道提供时，按渠道优先级择优，同级按权重随机分流
  • 某渠道失败会自动切换到下一个可用渠道
  • 渠道连续失败达阈值会自动熔断（冷却期内不再被选中），恢复后自动放行探测
  • 全部渠道不可用时返回 502/503

💡 若某模型返回「没有可用渠道」，通常是该模型专属渠道正在短暂熔断，稍后重试即可。

⑧ 错误码

  • 401 — 缺少 / 无效 / 过期令牌
  • 402 — 用户余额不足，或令牌额度已用尽
  • 403 — 令牌被禁用 / 无权访问该模型 / IP 不在白名单 / 用户被禁用
  • 429 — 触发限流（响应头带 Retry-After，单位秒）
  • 502 / 503 — 上游全部不可用（已尝试全部渠道）

错误体为 {"error":{"message":"...","type":"..."}}，与 OpenAI 一致，可直接用 SDK 捕获。

⑨ 常见问题

  • 能用上游厂商的原生 key 直接调本平台吗？　不能，返回 401 Invalid token。本平台只认自己签发的 sk- 令牌。
  • 请求会被转发到哪？　由平台按模型自动路由到已配置的上游渠道（Ollama 云端 / SLCH / 算力节点等）；你不必关心具体落到哪一家。
  • 换了模型名调用失败？　请用「模型目录」页列出的名称；不同上游对同一模型的命名可能不同，平台已做统一映射。
  • 响应里 content 为空但有 reasoning？　部分模型是推理模型，思考过程在 reasoning 字段，最终答案在 content；可适当调大 max_tokens。
  • 怎么换 key / 吊销？　在「令牌」页禁用或删除即可，立即生效，不影响上游。
